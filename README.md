# ask-devenv

Local development environment for the Ask AI assistant ecosystem.

Assembles the following repos via Docker Compose:

| Repo | Local URL |
|---|---|
| [ask-backend](https://github.com/Weezevent/ask-backend) | https://api.ask.local |
| [ask-frontend](https://github.com/Weezevent/ask-frontend) | https://ask.local |
| Qdrant | http://localhost:6333/dashboard |

HTTPS is handled by [Caddy](https://caddyserver.com/) with certificates generated by [mkcert](https://github.com/FiloSottile/mkcert).

## Prerequisites

- macOS / Linux
- Docker + Docker Compose v2
- [mkcert](https://github.com/FiloSottile/mkcert) — installed automatically by `setup.sh` via Homebrew if missing
- The sibling repos cloned next to this one:

```
parent/
├── ask-devenv/      ← you are here
├── ask-backend/
└── ask-frontend/
```

> Clone them with:
> ```bash
> git clone git@github.com:Weezevent/ask-backend.git
> git clone git@github.com:Weezevent/ask-frontend.git
> ```

## First-time setup

```bash
./setup.sh
```

This will:
1. Install the mkcert local CA (once per machine — requires sudo for Keychain/NSS)
2. Generate a TLS certificate for `ask.local` and `api.ask.local`
3. Add both domains to `/etc/hosts`
4. Create `.env` from `.env.example`

Then fill in the required values in `.env` (Keycloak client secret, Gigz API tokens, etc.) and you're ready.

## Running the stack

```bash
# Start everything (backend + frontend + qdrant + caddy)
docker compose up -d

# Follow ask-backend logs
docker compose logs -f ask

# Follow all
docker compose logs -f
```

| URL | What |
|---|---|
| https://ask.local | Frontend UI |
| https://api.ask.local/docs | Backend OpenAPI docs |
| https://api.ask.local/health | Backend health check |
| http://localhost:6333/dashboard | Qdrant dashboard |

## Common tasks

| Task | Command |
|---|---|
| Start stack | `docker compose up -d` |
| Stop stack | `docker compose down` |
| Rebuild after code change | `docker compose up -d --build ask` |
| Run backend tests | `docker compose run --rm ask-pytest` |
| Open Python shell (backend) | `docker compose run --rm ask-debug` |
| Wipe Qdrant data | `docker compose down -v` |

## How it works

```
                          ┌─────────────────────────────────────────┐
Browser                   │  Docker network (ask-devenv_default)    │
  │                       │                                         │
  │  https://ask.local    │  ┌──────────┐                           │
  ├──────────────────────►│  │  Caddy   │──► frontend:3000          │
  │                       │  │ (TLS     │                           │
  │  https://api.ask.local│  │  proxy)  │──► ask:8000               │
  └──────────────────────►│  └──────────┘                           │
                          │                                         │
                          │  ask-backend ──► qdrant:6333            │
                          │               ──► AWS Bedrock (HTTPS)   │
                          │               ──► Gigz APIs (HTTPS)     │
                          │               ──► Keycloak (HTTPS)      │
                          └─────────────────────────────────────────┘
```

Keycloak (`accounts.weezevent.com/realms/accounts-dev`) runs remotely — no local instance needed. Both frontend and backend point at the shared dev realm.

Hot-reload is enabled on both services:
- **ask-backend**: uvicorn `--reload`, source mounted from `../ask-backend/ask`
- **ask-frontend**: Vite dev server with HMR, source mounted from `../ask-frontend`

## Environment variables

See [`.env.example`](.env.example) for the full list with comments. Required at minimum:

| Variable | Description |
|---|---|
| `ACCOUNTS_CLIENT_SECRET` | Keycloak confidential client secret for `ask_backend_local` |
| `GIGZ_LOGS_TOKEN` | Bearer token for gigz-logs staging API |
| `GIGZ_FOREST_USER` / `GIGZ_FOREST_PASSWORD` | Basic auth for gigz-forest staging API |

AWS credentials (`AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY`) are optional if your local `~/.aws` is configured — you can mount it instead.

## Troubleshooting

**Certificate not trusted in browser**  
Run `mkcert -install` again, then restart your browser.

**`api.ask.local` or `ask.local` not resolving**  
Check `/etc/hosts` has both entries. Re-run `setup.sh` if needed.

**Port 443 already in use**  
Stop any local nginx/apache, or change the Caddy port mapping in `docker-compose.yml`.

**ask-backend can't reach Qdrant**  
`QDRANT_HOST` is hardcoded to `qdrant` (the Docker service name) in the compose file. Don't override it in `.env`.
